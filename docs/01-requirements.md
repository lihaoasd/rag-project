# 投标文档 RAG 系统 — 需求文档

> 版本: v1.0 | 日期: 2026-08-07 | 状态: 初稿

---

## 1. 项目概述

### 1.1 项目背景

在日常投标工作中，团队需要频繁查阅历史标书、招标文件等 PDF/Word 文档来获取信息。传统的关键词搜索无法覆盖语义层面的查询需求，且人工翻阅效率低下。本项目构建一个基于 RAG（Retrieval-Augmented Generation）的智能问答系统，对投标相关文档进行语义检索和智能问答，提升信息获取效率。

### 1.2 项目目标

1. 支持 PDF、Word 文档的上传与自动解析
2. 构建向量知识库，实现语义级检索
3. 基于大语言模型（LLM）对检索结果进行智能问答
4. 提供 Web 界面供业务人员使用

### 1.3 目标用户

| 序号 | 角色 | 描述 |
|------|------|------|
| 1 | 业务用户 | 上传投标文档、创建知识库、进行问答 |
| 2 | 系统管理员 | 管理模型配置、知识库维护 |

## 2. 功能需求

### 2.1 文档管理

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-01 | 文档上传 | 支持上传 PDF（.pdf）和 Word（.docx / .doc）格式文件 | P0 |
| F-02 | 文档解析 | 自动提取文档中的：纯文本内容、表格数据、图片中的文字（OCR）、文档元数据（文件名、页数、创建时间等） | P0 |
| F-03 | 文档列表 | 展示已上传的文档列表，支持按知识库筛选 | P1 |
| F-04 | 文档删除 | 支持删除已上传的文档，同步删除向量数据 | P1 |
| F-05 | 解析状态展示 | 展示文档解析状态（解析中 / 已完成 / 失败） | P1 |

#### 2.1.1 文档解析详细说明

| 序号 | 解析项 | 描述 | 处理方式 |
|------|--------|------|----------|
| 1 | 纯文本内容 | 段落文字、标题、列表等 | 直接提取 |
| 2 | 表格数据 | 文档中的表格 | 保留行列结构，转为结构化文本 |
| 3 | 图片中文字 | 文档内嵌图片所含文字（如扫描件、截图） | PaddleOCR 识别 |
| 4 | 文档元数据 | 文件名、页数、创建时间、文件大小 | 系统自动采集 |

### 2.2 知识库管理

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-06 | 创建知识库 | 创建独立的知识库，指定名称和描述 | P0 |
| F-07 | 删除知识库 | 删除知识库及其下所有文档和向量数据 | P1 |
| F-08 | 知识库列表 | 展示所有知识库，含文档数量和创建时间 | P1 |
| F-09 | 多知识库隔离 | 不同知识库的文档相互隔离，检索时需指定知识库 | P0 |

### 2.3 智能问答

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-10 | 文档问答 | 基于选中知识库的文档内容进行问答 | P0 |
| F-11 | 多轮对话 | 同一会话内支持多轮对话，保留上下文 | P0 |
| F-12 | 答案溯源 | 回答时附上引用的来源文档和片段 | P1 |
| F-13 | 流式输出 | 回答以流式方式逐字输出，提升体验 | P1 |

#### 2.3.1 问答交互流程

1. 用户选择目标知识库
2. 用户输入问题
3. 系统检索知识库中相关文档片段（Top-K）
4. 系统将检索结果与问题组装为 Prompt
5. 调用 LLM 生成回答，流式返回前端
6. 回答完成后附带引用来源信息

### 2.4 文档检索

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-14 | 语义检索 | 基于用户输入的关键词或自然语言描述，在知识库中语义检索相关文档片段 | P0 |
| F-15 | 检索结果展示 | 以列表形式展示检索结果，每条结果包含：相关文本片段、来源文档名、页码、相似度得分 | P0 |
| F-16 | 关键词高亮 | 检索结果中高亮与查询匹配的关键词 | P1 |
| F-17 | 原文跳转 | 支持从检索结果跳转查看原始文档对应页面 | P2 |

#### 2.4.1 检索交互流程

1. 用户选择目标知识库
2. 用户输入检索关键词或自然语言描述
3. 系统将查询文本向量化
4. 在 Milvus 中执行向量相似度搜索
5. 返回 Top-K 相关文档片段列表
6. 展示片段内容、来源文档、页码、相似度得分

## 3. 非功能需求

### 3.1 性能要求

| 序号 | 指标 | 要求 |
|------|------|------|
| 1 | 文档解析延迟 | 10MB 以内 PDF 在 30 秒内完成 |
| 2 | 问答首字延迟 | < 3 秒 |
| 3 | 向量检索延迟 | 单次检索 < 1 秒 |

### 3.2 可用性要求

1. Web 界面简洁直观，无需技术背景即可使用
2. 文档上传支持拖拽操作
3. 错误信息以友好方式提示用户

### 3.3 可扩展性要求

1. LLM 支持灵活切换（DeepSeek / OpenAI / 其他兼容接口）
2. Embedding 模型可通过 Xinference 灵活更换
3. 知识库数量、文档数量无硬性限制

### 3.4 安全性要求

1. 知识库之间数据严格隔离
2. 敏感配置（API Key 等）通过环境变量管理

## 4. 术语定义

| 序号 | 术语 | 说明 |
|------|------|------|
| 1 | RAG | Retrieval-Augmented Generation，检索增强生成 |
| 2 | Embedding | 向量嵌入，将文本转换为向量表示 |
| 3 | Milvus | 开源向量数据库，用于存储和检索文档向量 |
| 4 | LlamaIndex | RAG 开发框架，负责文档索引和检索管线 |
| 5 | Xinference | 开源模型推理平台，用于部署本地 Embedding 模型 |
| 6 | 知识库 | 一组文档的集合，作为检索的边界 |
