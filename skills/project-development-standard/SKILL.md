# 项目开发标准

> 版本：v1.0.0

## 目标

本 skill 将常见 LLM 编码错误约束为可执行流程：先想清楚、再写方案、精准修改、用测试验证。它偏向谨慎而非速度，简单任务可自行判断。

## 强制工作流

每次开发前完成以下步骤，缺一不可。

1. 澄清需求
   - 明确用户目标、成功标准和边界；多种理解必须列出，不默默选择。
   - 不确定时直接提问；有更简单方案时提出异议。
2. 检查设计文档
   - 查找需求文档、技术方案、接口文档等；文档必须按类别存放，缺失时先要求补齐，不直接编码。
   - 审查输入/输出、边界条件、系统交互、异常策略是否明确。
3. 编写开发方案
   - 保存到 `docs/plan/xxx-plan.md`。
   - 方案包含改动范围、实现步骤、关键伪代码、验证方式。
4. 最小化实现
   - 只实现需求要求的改动；不添加投机功能，不为一次性代码建抽象。
   - 遵循代码质量标准并匹配现有项目风格。
5. 记录修改
   - 每次代码、测试、配置、迁移或文档改动都必须追加修改记录。
   - 记录位置沿用项目约定；无约定时使用 `docs/changes.md`。
   - 至少记录日期、需求/问题、改动范围、关键文件、验证结果。
6. 验证并审计
   - 运行测试、执行验收，并逐行检查 diff 是否能追溯到需求。
   - 确认修改记录与本次 diff 一一对应。

## 任务类型

- **从 0 构建项目**：先产出需求文档、技术文档和明确项目结构，再分层实现。读取 `references/from-scratch.md`。
- **修改 bug**：先写复现测试，再定位根因并最小修复。读取 `references/bug-fix.md`。
- **需求变更**：先做影响分析并更新设计文档，再修改。读取 `references/requirement-change.md`。
- **补充单元测试**：按可观察行为、边界条件和隔离性编写测试。读取 `references/unit-test.md`。
- **所有编码**：执行高扩展、高可读、高复用与抽象边界检查。读取 `references/code-quality.md`。
- **修改记录**：每次修改结束前记录范围、原因与验证结果。读取 `references/change-record.md`。
- **文档管理**：新建、移动或归档文档时按类别存放。读取 `references/docs-classification.md`。
- **底线原则**：完整保留 CLAUDE.md 的详细准则。读取 `references/core-standards.md`。

## 代码质量底线

- 抽象必须有真实收益：消除重复、稳定扩展点、减少认知负担；不为想象场景设计。
- 代码优先可读：命名表达意图，函数职责单一，控制流直接。
- 复用要具体：复用已有模块/接口/工具，不复制粘贴，不强行统一。
- 扩展性来自稳定接口和清晰边界，不来自过度配置或提前抽象。

## 完成检查清单

- [ ] 需求、边界和成功标准已确认
- [ ] 设计文档已检查，缺失项已补齐
- [ ] `docs/plan/` 中已有可评审方案
- [ ] 未添加需求外功能
- [ ] 修改范围最小，diff 每行可追溯到需求
- [ ] 修改记录已更新，并与本次 diff 一一对应
- [ ] 新建/修改的文档已放入正确分类目录
- [ ] 已补或已更新必要测试
- [ ] 测试与验收通过
