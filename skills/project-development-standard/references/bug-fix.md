# 修改 Bug 要求

本文件用于“修复 bug/报错/异常/行为不正确”任务。修复前必须能稳定复现。

## 1. 复现

- 先写一个能复现 bug 的失败测试，或提供最小可复现步骤。
- 记录实际行为与期望行为，明确触发条件、输入、环境和副作用。
- 如果无法稳定复现，先找出最小触发路径，不猜测修复。

## 2. 根因分析

- 从现象沿调用链定位根因，不修表面症状。
- 检查边界条件、状态、并发/时序、外部依赖、异常处理和数据转换。
- 确认根因后，列出候选修复并选最小、最符合现有设计的一个。

## 3. 最小修复

- 只修改修复根因所需的代码；不顺手重构、不格式化无关代码、不删无关冗余。
- 匹配现有代码风格和错误处理方式。
- 不改变公开契约，除非 bug 本身来自契约错误；若必须变更，同步更新调用方与文档。

## 4. 回归测试

- 保留/新增覆盖原 bug 的测试，确保修复后通过，且不依赖修复细节。
- 增加相邻边界测试，避免同类输入再次回归。
- 运行相关模块全量测试，确认没有破坏已有行为。

## 5. 验证

- 运行测试、类型检查、lint、构建等项目既有验证命令。
- 手动或脚本验收关键场景。
- 如果接口/行为/配置发生变化，更新对应文档。
- 在修改记录中写入问题、根因、修复范围、回归测试与验证结果。

## 反模式

- 改测试去匹配错误代码。
- 删除无关代码后 bug 消失，却不理解根因。
- 用宽泛异常捕获掩盖问题。
- 在修复中夹带重构、升级依赖或格式调整。
