# 修改记录要求

本文件适用于所有任务类型。任何代码、测试、配置、迁移、接口、UI 或文档改动都必须留下记录，不能只靠对话记忆。

## 必须记录的内容

每次修改至少记录：

- 日期
- 需求/问题编号或描述
- 修改类型：新建/修复/变更/重构/测试/文档/配置
- 改动范围：涉及模块、文件、接口
- 改动原因
- 关键行为变化
- 验证方式与结果
- 相关测试

## 记录位置

- 优先遵循项目已有约定；如果项目已有 changelog/修改记录，就追加到那里。
- 无约定时，推荐使用 `docs/changes/` 分类目录，记录文件按日期或主题命名。
- 单次开发方案仍写入 `docs/plan/`，修改记录与方案分开保留。
- 有 git 时，commit message 也应简短说明本次改动范围和原因。
- 记录位置遵循 [docs-classification.md](docs-classification.md) 的目录约定。

## 记录模板

```markdown
## 2026-08-18 修复登录校验漏洞

- 需求/问题: ...
- 类型: bug-fix
- 改动范围: auth service, login API
- 关键文件: backend/... , tests/...
- 原因: ...
- 行为变化: ...
- 验证: pytest ... 通过；curl 验收通过
- 测试: 新增 test_...
```

## 完成标准

- 任何 diff 都能在修改记录中找到对应条目。
- 修改记录不是事后补的说明，而是在开发完成时与代码一起交付。
- 记录缺失视为任务未完成。
