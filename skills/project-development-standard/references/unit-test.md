# 单元测试要求

本文件用于“写测试/补测试/测试失败/重构后保测试”任务。

## 测试范围

- 单元测试验证单个逻辑单元，不依赖真实网络、数据库、文件系统、定时器和随机源。
- 核心业务规则必须测试；正常路径、边界值、非法输入、异常/状态转换至少覆盖主要分支。
- 集成测试覆盖跨模块/外部依赖的真实组合，不属于单元测试范围。

## 测试结构

- 使用 Arrange-Act-Assert 三段结构；每个测试只验证一个行为。
- 测试名表达条件与期望：如 `test_calc_balance_when_invalid_input_raises`；中文项目可延续既有命名风格。
- 断言可观察输出、返回值、状态或明确副作用；不断言私有实现细节。
- 测试代码也遵循可读性：共用准备逻辑抽到 fixture/helper，但不隐藏关键断言。

## 隔离与确定性

- 对外部依赖使用 mock/stub/fake；优先注入依赖而不是依赖全局状态。
- 固定时间、随机数、语言环境等环境变量，保证测试可重复。
- 不写依赖执行顺序的测试；每个测试独立创建所需状态并清理副作用。
- 避免 sleep 和真实并发等待；使用可注入时钟或同步工具。

## 覆盖与维护

- 新增功能同步补测试；bug 修复先写复现测试；需求变更更新相关测试。
- 测试失败时先判断是代码回归还是测试过期；过期测试在需求明确变化时更新。
- 不删除仍有效的测试；无用/重复测试应说明理由后清理。
- 保持测试运行时间短；慢测试标记为集成测试并单独运行。
- 新增、修改或删除测试都要在修改记录中说明动机和验证结果。

## 反模式

- 只测试实现过程而不测试行为。
- 为了覆盖率创建无断言的测试。
- mock 掉被测对象自身逻辑。
- 测试依赖真实网络、共享数据库或本机路径。
