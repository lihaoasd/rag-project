# WriteAI 需求文档（MVP）

> 版本：v1.0（2026-08-26）｜状态：待评审

## 1. 背景与目标

用户需要一个「专门写文章的 agent harness」：通过 Web 界面创建文章项目，由多个角色 Agent 协作完成从选题到成稿的多阶段写作流程，关键节点由人工审核把关。本项目为全新独立项目（与父目录 ai_bid_rag 无关）。

## 2. 目标用户

- 个人写作者 / 内容创作者，单机本地使用。
- 会使用浏览器、会填写 API Key、懂基本 Markdown。

## 3. 核心场景

1. 用户新建文章项目：输入主题与写作要求（受众 / 篇幅 / 风格 / 约束）。
2. 系统依次执行：**选题分析 → 资料搜集（本地知识库 RAG + 联网搜索）→ 大纲生成**。
3. 大纲产出后**暂停**，用户审阅、修改、批准。
4. **分节撰写**全文草稿。
5. **审校 Agent** 按质量清单审校并改写，最多 N 轮（默认 2）；每轮产出审校报告与修订稿。
6. 最终稿产出后**暂停**等待人工审核，批准后导出 Markdown。

## 4. 功能范围（MVP）

| 模块 | 功能 |
| --- | --- |
| 项目管理 | 创建 / 列表 / 查看 / 删除文章项目；查看阶段进度与各阶段产物 |
| 写作流水线 | 选题 → 资料 → 大纲 → 撰写 → 审校 五阶段；大纲与最终稿两处人工审核节点；失败阶段可重试；审校可追加轮次 |
| 本地知识库 | 上传或放入 md/txt 文件，自动分块索引；写作时检索相关片段注入上下文 |
| 联网搜索 | 可配置 Tavily 搜索；未配置 Key 时自动降级为仅本地检索并注明 |
| 审校 | 按质量清单审校并修订，多轮迭代，阈值达标提前结束 |
| 输出 | 全文 Markdown 预览与下载导出 |
| 设置 | LLM BaseURL / API Key / 模型、Tavily Key、审校轮数、知识库目录 |

## 5. 不做（边界）

- 不做多用户、登录与权限（本地单用户，仅监听 127.0.0.1）。
- 不做发布、SEO、Word/PDF 排版导出。
- 不做团队协作与多人审阅。
- 不做批量任务队列 / 并发写作。
- 不做移动端适配（桌面优先）。
- 不做 PDF/DOCX 知识文档解析（后续版本）。
- 不做流式输出（MVP 阶段完成后一次性呈现产物；列为后续扩展点）。

## 6. 成功标准

1. 无 API Key 时（LLM Mock 模式 + 无搜索 Key）整条流水线可端到端跑通并导出 Markdown。
2. 配置真实 LLM Key 后，一条示例文章可产出结构完整、可阅读的成稿。
3. 两处人工审核节点可暂停、可修改产物、可继续；任意阶段失败可重试。
4. 知识库检索生效：放入种子文档后，资料阶段产物中出现来自该文档的内容。
5. 服务端核心逻辑（状态机、流水线、RAG 检索）有单元测试覆盖且全绿。

## 7. 验收方式

- 单元测试：`npm test` 全绿（orchestrator 状态机、pipeline 顺序与审核点、RAG 分块与检索、LLM 客户端 Mock）。
- 端到端演示：`npm run dev` 启动后，用 Mock 模式创建项目跑通全流程并导出 Markdown。
- 真机冒烟：配置 DeepSeek（或任意 OpenAI 兼容）Key 后跑通一条示例文章。

## 8. 约束

- 运行环境：Windows / Node.js ≥ 20（当前 v24.19.0 已验证）。
- 技术栈：TypeScript + React（Vite）+ Express + SQLite（详见技术设计）。
- LLM 后端：OpenAI 兼容 API（DeepSeek / OpenAI / 通义等），Key 仅存本机配置。
- 数据仅存本机：SQLite 单文件 + Markdown 文件。
